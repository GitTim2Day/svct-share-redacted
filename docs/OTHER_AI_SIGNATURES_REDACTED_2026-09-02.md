# Other-AI signatures (redacted)
Date: 2026-09-02
Face: thin public. No specimen filenames. No household. No medical values. No addresses. No handles of living private persons.

Audience: engineers who build retrieval, tool-use, and source-rank.
Not a dump of another vendor’s chat. Patterns only.

## Use (advantageous if boxed)

1. Fast recap of a public class of names (drug, statute, agency).
2. Alias fluency when the alias is real (INN vs USAN).
3. Multi-page scroll that *looks* like coverage.

Box those as **draft recall**, never as the table.

## Avoid (do not let this finish a decision)

A. True fragment, wrong parent.
   A short official-looking list is assigned to the wrong statute or the wrong agency.
   Tokens can be real. The box is not.

B. Self-conflict sold as “corrected.”
   Two tables from the same generation family disagree on a binary flag.
   The word Corrected in a title is not a seal.

C. Container compliance ≠ claim compliance.
   A file can be a valid PNG / PDF / OOXML and still be rank-6 prose.
   Magic bytes beat the extension. A valid URI is not a trusted speaker.

D. One answer split into many files.
   Sequential screens are one scroll until proven otherwise.

E. Glue errors.
   Two substances or two senses welded into one caption.
   Treat as a defect, not as a new monograph.

F. People-search and brand-typo lures.
   Aggregator FAQ pages are not identity validators.
   A parseable chat URI that borrows a public name is still a lure.
   Subject-gate city, phone, relative, fax.

## Engineer checklist (cheap)

- Rank the speaker before merging the tokens.
- Bind bytes (magic) before binding the filename.
- Do not let a language model close an official list, a person cell, or a payment path.
- Empty header-only tables are recycle, not memory.
- Prefer one parent pointer over a second copy of the trunk.
